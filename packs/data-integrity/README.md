# Data integrity office pack

Protect saved data: compatibility across versions, schema changes, backups and old records. Reports; it never changes app code.

The pack adds one office with 4 members of its own and uses 1 core team agents by reference (nothing is copied twice). Give the lead (`data-lead`) a goal in plain words.

## Members

| Id | Title | What they do |
| --- | --- | --- |
| `data-lead` | Data Lead | Leads the data office: turns a change that touches stored data into checks for the team by name and reports the risk |
| `schema-diff-reviewer` | Schema Diff Reviewer | Compares the old and new shape of a saved file and lists every field added, removed, renamed or retyped |
| `backup-restore-checker` | Backup Restore Checker | Checks that a backup can really be restored: what it holds, what it misses and the steps |
| `archive-curator` | Archive Curator | Keeps finished records tidy: lists old runs and records by age and size and proposes what to archive |
| `data-migration` | Data Migration | Core team agent, used by reference |

## Sample tasks

1. **Diff two invented file shapes** (for `schema-diff-reviewer`): Compare the two invented sample files I name and list every field added, removed or changed, with the effect on an older version.
2. **Check an invented backup** (for `backup-restore-checker`): For the invented backup listing I name, say what it holds, what it misses and how to restore it.

## Limits

- Members prepare drafts and reports. They never send, post, pay or publish; Arsenale asks before any such step.
- A pack can only make the rules stricter.
